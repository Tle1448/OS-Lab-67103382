1. Inodes and Metadata:
In the `inode_inspector.py` script, we printed the "Inode
Number". If you rename the file using the Linux `mv` command,
will the Inode Number change? Why or why not? (Hint: Think about
how the OS separates the file name from the actual data).

The Inode Number will not change when the file is renamed using the Linux `mv` command. The file name is separate from the actual file data and its inode. The `mv` command changes the file name or directory entry, while the inode remains the same.


2. POSIX Permissions:
If you want to set a file's permission so that the Owner has
Read/Write/Execute (7), the Group has Read/Execute (5), and
Others have absolutely no access (0), what would be the 3-digit
octal number you pass into `os.chmod()`?

The 3-digit octal number is 750. Therefore, the code would be:

os.chmod(filename, 0o750)


3. The AI Context:
Why is it safer to rely on Operating System file permissions (like `os.chmod(0o444)`) to protect production model weights rather than relying solely on application-level logic or Python try-except blocks?

It is safer because the Operating System enforces file permissions at the kernel level. Even if an application has a bug or tries to write the production model, the OS can deny the write operation. This provides stronger protection than relying only on application-level logic or Python try-except blocks.
